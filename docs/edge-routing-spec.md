# エッジ描画仕様（あるべき描画結果）

本書は、スイムレーンレイアウトにおけるエッジ（矢印）描画の「あるべき結果」を
**機械検証可能な不変条件**として定義する。`scripts/verify-edge-routing.ts` が
本仕様の各ルールをレイアウト出力に対して点検する。レイアウトエンジン
（`src/layout/build-swimlane-layout.ts`）の変更は、本チェッカーを通過した状態で
コミットすること。

検証コマンド:

```bash
npx tsx scripts/verify-edge-routing.ts
```

## S1. 経路の基本形

- **S1-1 直交性**: すべてのエッジは水平・垂直セグメントのみからなる直交折れ線である。
- **S1-2 端点**: 経路の始点は始点ノードの境界上、終点は終点ノードの境界上にある。
- **S1-3 ノード回避**: 経路セグメントは、自身の始点・終点ノードを除くいかなる
  ノード矩形とも交差しない。

## S2. 接続位置（アンカー）

- **S2-1 単独接続は中央**: ノードのある辺（上/下/左/右）に接続するエッジ束が
  1つだけなら、その辺の中央に接続する。
  - 例外 E1: 同一レーン迂回エッジは、始点と終点のXが一致するとExcelコネクタで
    経路形状を表現できないため、進入または退出の一方が中央を譲ることを許す。
- **S2-2 decisionは頂点**: decision（ひし形）への上辺進入と真下退出は、束の数に
  かかわらず常に中央（頂点）に接続する。複数の進入は頂点手前で合流する。
  - 例外 E1 は decision にも適用される。
- **S2-3 左右順の整合**: 同じ辺に複数束が接続する場合、接続位置の左右順は
  各束の到来方向の左右順と一致する（順序の逆転で交差を作らない）。
  ※ S4-1/S4-2 の交差検査で担保する。

## S3. 直線性・簡潔性

- **S3-1 直進の直線化**: 同一レーンで間に他ノードがない前進エッジは、両端の辺が
  他の接続と競合しない限り、曲がりのない1本の垂直線で描く。
- **S3-2 曲がり数の上限**: 経路の曲がりは4回以下とする（＝Excelコネクタの忠実
  写像範囲に収まる形状クラス）。

## S4. 交差・重なり

- **S4-1 同一始点の非交差**: 同じノードから出るエッジ同士は交差しない。
- **S4-2 同一終点の非交差**: 同じノードに入るエッジ同士は交差しない。
  合流束が末尾区間を共有することは交差とみなさない。
- **S4-3 部分重なりの禁止**: 異なるエッジの同方向セグメントは同一線上で部分的に
  重ならない。例外として、同じターゲットの同じアンカーへ合流する束の共有末尾
  （トランク）は許す。
- **S4-4 交差数の監視**: 全体の交差数は最小化を目指す指標として計測・報告する
  （NP困難のため絶対値のルール化はしない。増加はレビューで判断する）。

## S5. Excel出力との整合

- **S5-1 形状クラス**: すべての経路は、Excelコネクタへ忠実に写像できる形状
  （V / H / HV / VH / HVH / VHV / HVHV / VHVHV）に収まる。
- **S5-2 接続点の一致**: 画面のアンカー位置とExcelの接続サイト（cxnLst）は
  同じ並び順で対応する（`ANCHOR_PERCENTS` / `SIDE_ANCHOR_OFFSETS` の順序を
  変更する場合は `flow-exporters.ts` と同時に変更する）。

## 優先順位

ルールが衝突する場合の優先順位は S5（Excel忠実性） > S2-2（decision頂点） >
S2-1（単独中央） > S4（交差・重なり） > S3（直線性） とする。
例外を適用した箇所はチェッカーが「例外」として報告し、黙認はしない。
